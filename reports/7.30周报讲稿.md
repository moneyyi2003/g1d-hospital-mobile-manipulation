# 第 1 页：本周工作（约 55 秒）

这周的重点是搭建 G1-D 的双脑协同 Agent，代码主要放在
`g1d_dual_brain_agent` 目录。这里的“双脑”指的是把全局导航和局部操作分开：
VLN 继续负责长距离导航、场景搜索和底盘靠近，VLA 以后负责机器人到达目标附近之后的
局部操作。

新框架把任务拆成五类技能：区域导航、实时找物、靠近与对齐、局部操作以及物理验证。
Executive 会根据当前任务状态动态选择技能，而不是把 VLN 和 VLA 写成固定的两步调用。
同时加入了共享对象记忆、底盘和机械臂的互斥控制，以及按照失败原因重新选择技能的恢复
逻辑。

目前完成的是 Agent 框架、路由和安全边界，还没有把它表述成双臂抓取已经跑通。

# 第 2 页：主要流程与设计思路（约 1 分 10 秒）

整个流程从 NAVIGATE 开始，先把机器人带到目标区域；如果目标还不可见，就进入
SEARCH_OBJECT；找到目标之后，通过 APPROACH_AND_ALIGN 调整底盘位置、距离和视角；
条件满足后才允许进入 MANIPULATE；最后由独立的 VERIFY 判断任务是否真的成功。

这样设计的第一个原因是 VLN 和 VLA 的工作尺度不同。VLN 更擅长地图约束下的全局移动，
VLA 更适合目标附近的短时视觉动作。将两者解耦之后，不需要联合训练，任何一侧升级时
都可以只替换对应后端。

第二个原因是安全和可解释性。Executive Agent 只拆任务、选技能、管理进度，不直接给
轮子或机械臂下控制量。VLN 和 VLA 通过对象级世界记忆交换信息，包括对象 ID、全局与
局部位姿、可见性、可达性、携带状态和最近一次失败原因。

另外，底盘、右臂和右手设置了互斥控制租约，避免两个技能同时控制同一个执行器。失败
也不是简单地从头再来：路径被挡就回导航，找不到目标就回搜索，够不到就重新对齐，
物体滑落则回到对齐或操作。对于 TF 缺失、碰撞风险、对象歧义或 VLA 不可用等情况，
系统会直接阻塞，也就是 fail-closed，不会为了跑通流程而输出不可信动作。

# 第 3 页：Agent 如何实现两大脑切换（约 1 分 15 秒）

这一页具体对应代码说明切换是怎么实现的。

首先，`planner.py` 把输入整理成 Mission 和 TaskGoal。Executive 进入执行循环后，
`executive.py` 里的 `_select_skill()` 会读取当前目标的 GoalProgress，以及共享记忆中
目标对象的观测是否新鲜。如果还没到目标区域，就选择 NAVIGATE；对象不存在或观测超过
有效时间，就选择 SEARCH_OBJECT；对象可见但还没完成对齐，就选择
APPROACH_ALIGN；对齐成功后才选择 MANIPULATE，操作返回后再进入 VERIFY。

得到 SkillKind 后，`SkillRegistry.resolve()` 会找到对应执行器。
`LegacyVlnSkillExecutor` 只处理 NAVIGATE 和 APPROACH_ALIGN，把它们转换成已有导航侧
的语义导航或预抓取停靠步骤；`LegacyVlaSkillExecutor` 只接受 MANIPULATE，并把共享
世界记忆和当前指令交给 VLA adapter。技能返回统一的 SkillResult，Executive 再把结果
写回进度和对象记忆，然后进入下一轮选择。

切换时还有控制权保护。`control.py` 会在技能执行前申请资源租约：导航、搜索和对齐占用
底盘，操作占用底盘、右臂和右手；执行结束后释放。若资源已经被占用或执行期间租约丢失，
任务会阻塞。因此代码中并不是简单设置一个 VLN/VLA 开关，而是状态判断、技能分派、
结果回写和重新判断组成的循环。

# 第 4 页：架构图（约 40 秒）

这一页整体展示双脑协同结构。左边是 VLN Brain，输入来自 G1-D 机载 RGB，经过
LingBot RGB-only 建图、SAM3 语义对齐、occupancy 和审核地点库，最终负责全局导航、
搜索以及底盘靠近。

右边是 VLA Brain，定位为局部操作模块，后续接收头部或腕部 RGB，在目标已经确认、
底盘已经停稳、机械臂可达的条件下执行抓取、放置、开门或按钮等动作。

中间的 Executive Agent 和共享对象级世界记忆把两侧连接起来。下方五个方框对应刚才
介绍的五阶段流程，失败后按照结构化原因进行有界重规划。最下面的 Control Arbiter
保证同一时刻只有一个技能持有控制权，所有能力先在同一个 Isaac Sim 会话中连续验证，
再考虑 sim-to-real。

# 第 5 页：下周任务（约 1 分钟）

下周准备先接入一个简单的 OpenVLA 看实际效果。第一步只做最小诊断链：把当前头部或
腕部 RGB 和一条简短英文操作指令送给模型，跑通单次推理，同时记录动作输出格式、推理
延迟和显存占用。

第二步是动作适配。OpenVLA 的输出先按照末端位姿增量理解，不能直接当成 G1-D 的关节角。
在任何仿真执行之前，还要经过坐标系转换、右臂 IK、碰撞检测和关节限位检查。

第三步是在 Isaac Sim 中选择一个物体和一个简单动作，观察
“目标对齐—模型推理—动作执行—结果验证”这条最小闭环。这里的目标主要是验证接口和
发现问题，不追求一次就实现复杂抓取；失败时会保留对应图像、动作和结构化原因。

等双臂 VLA 训练完成之后，再把临时 OpenVLA backend 换成正式双臂模型，并补齐双臂
动作空间、左右臂时序同步、碰撞约束以及独立的操作成功判据。
